# 문제 해결

## 접속이 안 될 때

1. 서버 PC에서 `http://localhost:8082`가 열리는지 확인합니다. 열리지 않으면 서버가 꺼져 있는 것입니다.
    - 트레이에 파란 달력 아이콘이 없으면 시작 메뉴의 **leave-flow 휴가원 관리**로 켭니다.
    - 켜자마자 "서버가 종료되었습니다" 창이 나오면 [로그](#로그)에서 이유를 확인합니다.
2. 서버 PC에서만 열리면 네트워크 프로필이 **개인**인지, 방화벽 규칙 `leave-flow`가 있는지(다시 설치하면 다시 만듦), 서버 PC의 IP가 바뀌지 않았는지 확인합니다 ([접속 주소와 네트워크](operation.md#접속-주소와-네트워크)).
3. "서버에 연결할 수 없습니다"가 잠깐 보였다가 사라지면 업데이트·복구로 서버가 다시 시작된 것입니다.

## 포트 충돌

`8082번 포트를 이미 다른 프로그램이 사용 중`이라고 나오면 `update-config.ps1 -Port 8090`(설치 전이면 `install.ps1 -Port 8090`)으로 포트를 바꾸고, 직원들의 접속 주소도 바꿉니다.

## 로그

- `<설치 폴더>\logs\server-YYYYMMDD.log`: 서버·launcher 기록 (30일 보관)
- 관리 → **변경 이력**: 데이터 변경과 백업·복구·업데이트 기록

## NAS 백업 오류

`NAS 복사 실패`가 보이면 NAS가 켜져 있는지, 주소가 맞는지, 출결 PC에 로그인한 계정이 그 폴더에 쓸 수 있는지 확인합니다 ([NAS 백업](backup.md#nas-백업)). 로컬 백업은 계속 만들어집니다.

## 공휴일이 들어오지 않을 때

공휴일은 서버를 켤 때만 구글 캘린더에서 가져옵니다. 서버를 켤 때 인터넷이 안 되면 건너뛰고 [로그](#로그)에 `[holiday] 구글 캘린더 공휴일 가져오기 실패`가 남습니다. 인터넷을 확인한 뒤 트레이에서 종료하고 시작 메뉴의 **leave-flow 휴가원 관리**로 다시 켜거나, 필요한 날을 직접 추가합니다.

## 업데이트에 실패했을 때

- 새 버전이 정상적으로 시작되지 않으면 **이전 버전과 업데이트 전 DB로 자동으로 되돌리고** 관리 → 백업·업데이트에 안내가 나옵니다. 그 버전은 자동으로 다시 설치하지 않습니다.
- 내려받기·무결성 확인에 실패하면 아무것도 바뀌지 않고, 다음 확인 때 다시 시도합니다.

## 이전 버전으로 돌아가기

1. GitHub Releases에서 이전 버전의 설치 프로그램이나 zip을 받아 다시 설치합니다. 설치하기 전에 지금 DB를 `pre-update`로 백업합니다.
2. 자동 업데이트는 문제가 있던 버전을 건너뛰고, 그보다 높은 버전이 나오면 설치합니다. 이 버전에 계속 머물려면 `update-config.ps1 -AutoUpdate off`로 자동 설치를 끕니다.
3. 새 버전에서 DB 구조가 바뀌었다면 이전 버전의 화면이 이상할 수 있습니다. 그때는 그 업데이트 직전의 `pre-update` 백업으로 [복구](backup.md#복구)합니다.
