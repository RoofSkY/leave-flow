# leave-flow 운영 가이드

사무실 출결 PC에 leave-flow(휴가원 관리)를 설치하고 운영하는 방법입니다. 개발 지식이 없어도 따라 할 수 있도록 썼습니다.

- 서버: 사무실 출결 PC (Windows 11) 한 대
- 접속: 사무실 안의 PC에서 브라우저로 `http://<출결 PC IP>:8080`
- 직원 PC에는 아무것도 설치하지 않습니다.

---

## 1. 설치

### 준비물

- 출결 PC의 **관리자 계정**
- 인터넷 연결 (설치할 때 Node.js를 자동으로 받습니다. Node.js를 따로 설치할 필요는 없습니다.)
- 설치 프로그램 `leave-flow-setup-<버전>.exe` — GitHub 저장소의 **Releases** 화면에서 받습니다.

> leave-flow는 설치 폴더 안에 **전용 Node.js**(`<설치 폴더>\node`)를 따로 둡니다. PC에 있는 다른 Node.js나 Python, auto-ansimtalk와 서로 영향을 주지 않습니다.

### 순서

1. `leave-flow-setup-<버전>.exe`를 **더블클릭**합니다.
   - "이 앱이 디바이스를 변경하도록 허용하시겠어요?"가 나오면 **예**를 누릅니다.
   - "Windows의 PC 보호" 창이 나오면 **추가 정보** → **실행**을 누릅니다 (서명하지 않은 프로그램이라 나오는 안내입니다).
2. 추가 작업을 고릅니다. 둘 다 처음에는 켜져 있습니다.
   - **Windows에 로그인하면 자동으로 실행** — 끄면 바로가기로 직접 켜야 합니다.
   - **바탕화면 바로가기 만들기**
3. **설치**를 누르면 진행 상황이 나오고, 끝나면 **휴가원 관리 화면 열기**로 바로 열 수 있습니다.
   설치하지 못하면 이유가 창에 나옵니다. 원인을 해결하고 다시 실행하세요.
4. 출결 PC의 IP를 확인하고(2장), 다른 PC의 브라우저에서 `http://<출결 PC IP>:8080`으로 접속되는지 확인합니다.

설치 폴더는 설치하는 계정의 **문서 폴더 안 `leave-flow`**(예: `C:\Users\<계정>\Documents\leave-flow`)가 기본이며, 설치할 때 바꿀 수 있습니다.
이 문서에서 `<설치 폴더>`는 이 폴더를 뜻합니다.
문서 폴더가 OneDrive와 동기화되고 있으면 DB 파일이 동기화되면서 문제가 생길 수 있으니 OneDrive 밖의 폴더(예: `C:\leave-flow`)를 고르세요.
NAS 백업 폴더는 설치한 뒤 관리 → **설정**의 **NAS 백업 폴더**에서 지정할 수 있습니다 (6장).

#### 옵션을 주어 설치하기 (zip)

다른 포트·폴더를 쓰거나 인터넷이 안 될 때는 배포 파일 `leave-flow-<버전>.zip`의 압축을 풀고
`scripts\install.cmd`를 더블클릭하거나(검은 창에 진행 상황이 나옴), 아래처럼 **관리자 PowerShell**에서 옵션을 주어 실행합니다.
(시작 메뉴에서 PowerShell을 오른쪽 클릭 → "관리자 권한으로 실행")

```powershell
cd "압축을 푼 폴더"
powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1 -Port 8090 -NasBackupDir "\\NAS주소\backup\leave-flow"
```

| 옵션 | 뜻 | 기본값 |
|---|---|---|
| `-InstallDir` | 설치 폴더 | 이미 설치된 폴더, 처음이면 `문서\leave-flow` |
| `-Port` | 접속 포트 (5000번은 사용 불가) | `8080` |
| `-NasBackupDir` | NAS 백업 폴더 | 없음 |
| `-UpdateRepo` | 자동 업데이트할 GitHub 저장소 `owner/repo` | 배포 파일에 적힌 저장소 |
| `-ReleaseZip` | 배포 파일 경로 | 스크립트가 있는 폴더 |
| `-NodeZip` | 미리 받아 둔 `node-v24.x.x-win-x64.zip` (인터넷이 안 될 때) | nodejs.org에서 받음 |
| `-NoAutoStart` | Windows 로그인 시 자동 실행하지 않음 | 자동 실행함 |
| `-DesktopShortcut` | 바탕화면 바로가기 만들기 (주지 않으면 있던 바로가기를 지움) | 만들지 않음 |

### 자동 실행 방식

- 설치할 때 이 PC에 로그인해 있던 Windows 계정이 **로그인하면** 자동으로 실행됩니다 (작업 스케줄러의 `leave-flow` 작업).
  설치할 때 자동 실행을 껐으면 로그인해도 켜지지 않으므로 바로가기로 켭니다.
  **로그인하기 전에는 서버가 돌지 않으므로** 출결 PC는 운영 시간에 그 계정으로 로그인해 두세요.
- 실행되면 작업 표시줄 오른쪽 알림 영역(트레이)에 **파란 달력 아이콘**이 생깁니다. 아이콘이 안 보이면 `^`(숨겨진 아이콘 표시)를 누르세요.
  - **웹페이지 열기** (아이콘 더블클릭도 같음): 이 PC의 브라우저로 휴가원 관리 화면을 엽니다.
  - **종료**: 서버를 끕니다. **다른 PC에서도 접속할 수 없게 되므로** 확인 창이 한 번 더 나옵니다.
- 종료한 뒤 다시 켜려면 시작 메뉴(또는 바탕화면)의 **leave-flow 휴가원 관리**를 실행합니다 (이미 켜져 있으면 웹페이지만 엽니다). 자동 실행이 켜져 있으면 Windows에 다시 로그인해도 켜집니다.
- 서버는 그 Windows 계정 권한으로 실행되고, NAS에도 그 계정으로 접근합니다 (6장 "NAS 백업 설정과 계정").

### 다시 설치·버전 바꾸기

새 설치 프로그램(exe)이나 `install.cmd`를 다시 실행하면 됩니다. **데이터(`data`), 백업, `config.json`은 그대로 둡니다.**
다른 버전으로 바꿔 설치하면:

- 먼저 지금 DB를 `backups\`에 백업합니다 (`…-pre-update.db`). 백업을 만들지 못하면 버전을 바꾸지 않고 멈춥니다.
- 새 버전을 시험해 보고, 60초 안에 정상적으로 시작되지 않으면 **이전 버전으로 자동으로 되돌리고 DB도 방금 만든 백업으로 되돌립니다.**
  이때 설치 창에는 설치를 마쳤다는 안내 대신
  `새 버전 … 이(가) 정상적으로 시작되지 않아 …(으)로 되돌렸습니다: (이유)`가 나옵니다. 이유는 `logs` 폴더의 로그에서 확인하세요.
- **낮은 버전으로 바꾸면**(예: 0.3.0에 문제가 있어 0.2.0 zip으로 다시 설치) 자동 업데이트가 곧바로 0.3.0을 다시 설치하지 않도록
  0.3.0을 건너뛰게 기록합니다. 설치 창에 노란 안내가 나옵니다. 그보다 **높은 새 버전**(예: 고친 0.3.1)이 나오면 자동으로 설치됩니다.
  새 버전이 나와도 지금 버전에 계속 머물려면 `update-config.ps1 -AutoUpdate off`로 자동 업데이트를 끄세요 (4장).

### 설치 폴더

```
<설치 폴더>\     (기본: 문서\leave-flow)
  node\            전용 Node.js
  tray.ps1         트레이 아이콘 (로그인 시 자동 실행 대상, launcher.mjs 를 실행)
  launcher.mjs     서버를 실행하고 감시하는 프로그램
  versions\0.1.0\  프로그램 (버전별)
  state.json       지금 실행할 버전 기록 (직접 고치지 마세요)
  config.json      설정
  data\            DB (leave-flow.db)  ← 가장 중요한 데이터
  backups\         로컬 백업
  logs\            로그
  updates\         내려받은 업데이트 파일
```

### 제거

Windows **설정 → 앱 → 설치된 앱**에서 **leave-flow 휴가원 관리**를 제거합니다 (zip으로 설치했으면 `scripts\uninstall.cmd`를 더블클릭).
자동 실행·바로가기·방화벽 규칙·프로그램 파일을 지우고 **데이터와 백업은 남깁니다.**
설치 폴더까지 모두 지우려면 관리자 PowerShell에서 `uninstall.ps1 -RemoveData`를 실행합니다 (확인을 위해 '삭제'를 입력해야 합니다).

## 2. 접속 주소, 고정 IP, 방화벽

- 접속 주소: `http://<출결 PC IP>:<포트>` (예: `http://192.168.100.○○:8080`). 출결 PC 자신에서는 `http://localhost:8080`.
- **고정 IP**: 출결 PC의 IP가 바뀌면 직원들이 접속할 수 없습니다. ipTIME 공유기 관리 화면(보통 `http://192.168.0.1` 또는 `192.168.100.1`)
  → 고급 설정 → 네트워크 관리 → **DHCP 서버 설정**에서 출결 PC를 "수동 등록(IP 예약)"해 두세요.
- 직원 PC 브라우저에 **즐겨찾기**로 접속 주소를 등록해 두면 편합니다.
- **방화벽**: 설치할 때 Windows 방화벽에 `leave-flow` 규칙(해당 포트, **개인 네트워크에서만** 허용)을 만듭니다.
  출결 PC의 네트워크가 "공용"으로 되어 있으면 다른 PC에서 접속할 수 없으니
  설정 → 네트워크 및 인터넷 → 이더넷(또는 Wi-Fi) → **네트워크 프로필 유형: 개인**으로 바꾸세요.
- 사무실 밖(인터넷)에서는 접속할 수 없습니다. 공유기에서 포트 포워딩을 하지 마세요.

## 3. auto-ansimtalk와 함께 쓰기

같은 출결 PC에서 auto-ansimtalk(`127.0.0.1:5000`)가 실행 중입니다. 서로 영향을 주지 않도록 완전히 분리되어 있습니다.

- 포트: leave-flow는 **5000번을 절대 쓰지 않습니다** (설정해도 시작하지 않음). 기본 8080.
- 폴더: leave-flow는 `<설치 폴더>`만 사용합니다. auto-ansimtalk 폴더는 건드리지 않습니다.
- 실행 환경: leave-flow 전용 Node.js를 쓰므로 PC의 Python·다른 프로그램 설치와 무관합니다.
- 설치·제거 스크립트는 `<설치 폴더>\node\node.exe`로 실행된 프로세스만 멈춥니다.

## 4. 설정 파일 (config.json)

`<설치 폴더>\config.json` — 설치할 때 만들어집니다. 메모장으로 고칠 수 있고, 고친 뒤에는 **다시 시작**해야 적용됩니다.
가장 쉬운 방법은 관리자 PowerShell에서 `update-config.ps1`을 쓰는 것입니다 (값 바꾸기 + 다시 시작을 한 번에).

```powershell
cd <설치 폴더>\versions\<버전>\scripts
powershell -ExecutionPolicy Bypass -File .\update-config.ps1 -NasBackupDir "\\NAS주소\backup\leave-flow"
powershell -ExecutionPolicy Bypass -File .\update-config.ps1 -Port 8090      # 방화벽 규칙도 함께 바뀜
powershell -ExecutionPolicy Bypass -File .\update-config.ps1 -AutoUpdate off # 자동 설치 끄기 (확인은 계속)
powershell -ExecutionPolicy Bypass -File .\update-config.ps1 -DisableNas     # NAS 백업 끄기
powershell -ExecutionPolicy Bypass -File .\update-config.ps1 -DisableUpdates # 업데이트 기능 끄기 (updateRepo를 null로)
```

| `update-config.ps1` 옵션 | 뜻 |
|---|---|
| `-Port` | 접속 포트 (방화벽 규칙도 함께 바뀜) |
| `-NasBackupDir` | NAS 백업 폴더 |
| `-DisableNas` | NAS 백업 끄기 (`nasBackupDir`을 `null`로) |
| `-UpdateRepo` | 업데이트 저장소 `owner/repo` |
| `-DisableUpdates` | 업데이트 기능 끄기 (`updateRepo`를 `null`로) |
| `-AutoUpdate on` / `off` | 새 버전 자동 설치 켜기/끄기 |
| `-BackupTime`, `-BackupKeepDays` | 자동 백업 시각, 보관 일수 |

> 관리자 PowerShell(5.1)에서는 `-NasBackupDir ""`처럼 **빈 값을 넘기면 오류**가 납니다. 끌 때는 `-DisableNas`, `-DisableUpdates`를 쓰세요.
> (`-NasBackupDir none`, `-UpdateRepo none`도 같은 뜻입니다.)

| 항목 | 뜻 | 기본값 |
|---|---|---|
| `port` | 접속 포트. **5000 사용 불가** | `8080` |
| `nasBackupDir` | NAS 백업 폴더 (예: `"\\\\NAS주소\\backup\\leave-flow"` — JSON에서는 `\`를 두 번 씀). 없으면 `null` | `null` |
| `backupTime` | 매일 자동 백업 시각 `"HH:MM"` | `"12:30"` |
| `backupKeepDays` | 백업 보관 일수 (로컬·NAS 모두) | `30` |
| `updateRepo` | 자동 업데이트할 공개 GitHub 저장소 `"owner/repo"`. 없으면 업데이트 기능 꺼짐 | 배포 파일 값 |
| `autoUpdate` | 새 버전을 자동으로 설치할지. `false`면 확인만 하고 설치는 관리 화면에서 직접 | `true` |
| `updateCheckHours` | 새 버전 확인 주기(시간). 1 ~ 576(24일) 사이로 쓰고, 그보다 크면 576시간, 숫자가 아니면 6시간으로 확인 | `6` |
| `dataDir`, `backupDir` | DB·로컬 백업 폴더 (보통 바꾸지 않음) | `data`, `backups` |
| `host` | 접속을 받을 주소 (보통 바꾸지 않음). 특정 IP로 정하면 launcher·설치 스크립트도 그 주소로 서버 상태를 확인 | `0.0.0.0` |
| `allowedHosts` | IP 대신 이름으로 접속하게 할 때 그 이름 목록 (예: `["leave-pc"]`). IP 주소·`localhost`·출결 PC 이름은 항상 허용되고, 그 밖의 이름으로 접속하면 "허용되지 않은 주소" 안내가 나옴. 직원들은 보통 IP로 접속하면 됨 | `[]` |

**다시 시작하는 방법**: 트레이 아이콘의 **종료** → 시작 메뉴의 **leave-flow 휴가원 관리**. `update-config.ps1`은 값을 바꾼 뒤 알아서 다시 시작합니다.

## 5. 처음 설정 순서

처음 설치하면 **휴가 종류·직원·부여 내역이 모두 비어 있습니다** (법정공휴일만 자동으로 들어 있음). 관리 화면에서 아래 순서로 입력하세요.

1. **휴가 종류** — 연차, 병가, 공가, 특별휴가, 대체휴가 등 사무실에서 쓰는 종류를 모두 등록합니다.
   잔여 방식은 **추가할 때 정하고, 사용 기록이 생기면 바꿀 수 없으니** 신중히 고르세요.
   - 연도별: 해마다 새로 시작 / 누적: 해를 넘겨 쌓임
   - 정한 날짜에 소멸: 매년 소멸일(예: 2월 28일)이 지나면 남은 양이 사라지고 다음 날부터 새로 셈
   - 부여 후 기간: 부여일부터 정한 개월 수가 지나면 그 부여에서 남은 양이 사라짐 (먼저 사라질 부여부터 사용)
   - 소진: 누적처럼 해를 넘겨 쌓임 (잔여에서 차감하는 종류만). `남은 양이 없으면 휴가원에서 숨김`(기본 켜짐)을 켜 두면 남은 양이 없는 직원(한 번도 부여받지 않은 직원 포함)은 휴가원 작성의 종류 목록과 휴가원 양식(휴가현황 표·체크박스)에서 빠짐. 그 휴가원에서 쓴 종류는 그대로 나오고, 다시 부여하면 다시 나옴

   일부 직원만 쓰는 종류(예: 사회복무요원 특별휴가)는 **적용 대상**을 `소속·구분·직원 선택`으로 바꾸고 소속, 구분, 직원을 고르세요. **소속과 구분을 함께 고르면 둘 다 맞는 직원만** 대상이고(예: `아동사업부` + `직원` → 아동사업부의 직원), 따로 고른 직원은 조건과 관계없이 더해집니다. 다른 직원의 휴가원 작성·부여·잔여 현황에는 그 종류가 나오지 않습니다.
   **직원·요원·강사처럼 대상마다 소멸일이 다른 연차**는 종류를 나눠 등록하세요. 이름은 `연차(직원)`·`연차(요원)`·`연차(강사)`처럼 다르게, **표시 이름은 모두 `연차`** 로 하고, 적용 대상은 각각의 구분으로 정합니다. 휴가원과 양식에는 "연차"로 나오고, 부여는 종류마다 따로 합니다. 한 직원에게 "연차"가 둘 이상 적용되게 저장하면 막고 누가 겹치는지 알려 줍니다.
   소속·구분으로 고르면 새로 온 직원에게도 자동으로 적용됩니다. 직원으로만 고른 경우에는 새 직원을 휴가 종류 수정에서 따로 추가하세요.

   부여량·잔여량은 `[ ]일 [ ]시간` 칸에 직접 입력합니다. **1일은 그 직원의 하루 근무시간**입니다 (점심 제외. 09:00~18:00 → 8시간, 10:00~16:00 → 5시간). 연차 15일이면 근무시간과 관계없이 `15일`로 넣으면 되고, 여러 명에게 한 번에 부여해도 직원마다 알맞게 계산됩니다. 하루 근무시간 이상 입력한 시간은 일로 넘어갑니다.
   (예: 대체휴가는 누적 또는 부여 후 기간, 특별휴가는 연도별)
2. **설정** — 근무시간 기본값과 소속·구분 목록을 정합니다.
   시간외근무로 적립할 휴가 종류는 설정에서 정하지 않고, **시간외근무 신청서를 쓸 때 대상자마다 고릅니다** (처음에는 비어 있음). 목록에는 그 직원에게 적용되는 활성 종류만 나오므로, 직원용·요원용 대체휴가처럼 대상마다 종류가 따로 있으면 직원에게는 대체휴가(직원), 요원에게는 대체휴가(요원)를 고르면 됩니다. 이미 적립된 신청서도 수정에서 종류를 바꾸면 적립이 바꾼 종류로 다시 만들어집니다.
   (직원 소속·구분은 이 목록에서 고르므로 직원보다 먼저 등록하세요. 사회복무요원 구분을 만들고 `사회복무요원 특별휴가 대상`을 켜야 그 구분의 직원이 사회복무요원 특별휴가·특별휴가(시상) 신청서 대상자로 나옵니다.)
3. **직원** — 성명, 소속, 색상, 근무 요일, 근무시간, 결재칸(휴가원 결재란에 나올 담당·팀장·센터장·대표), 구분
4. **기존 잔여량** — 프로그램을 쓰기 전까지의 올해 총 부여량과 현재 잔여량 (도입할 때 한 번)
5. **부여 내역** — 올해 부여량 (새해에는 연초에 직접 입력)
6. 공휴일·센터 휴무일 확인 (빠진 대체·임시공휴일, 센터 휴무일 추가)

### 직원·휴가 종류 영구 삭제

퇴사자는 보통 **비활성화**만 하면 됩니다. 잘못 만든 직원·휴가 종류를 정리하거나 직원 정보를 완전히 지워야 할 때는, 비활성화한 뒤 `비활성 포함`을 켜고 `삭제`를 누릅니다.

- 기록이 없으면 확인 한 번으로 지워집니다.
- 기록이 있으면 남는 문서와 부여·기존 잔여 건수가 나오고, 이름을 그대로 입력해야 지워집니다. 지우기 직전에 자동으로 백업(`영구 삭제 전`)을 만듭니다.
- **직원·휴가 종류를 지워도 휴가원과 시간외근무 신청서는 지우지 않습니다.** 작성할 때의 성명·종류 이름으로 계속 보이고 출력할 수 있지만, 삭제된 직원의 문서는 수정·취소·복구할 수 없습니다.
- 휴가원이 있는 직원은 **휴가원 양식의 휴가현황이 삭제 전과 똑같이 나오도록** 부여·기존 잔여를 지우지 않고 관리 화면에서만 숨겨 둡니다.
- 시간외근무 신청서에서 적립 종류로 고른 휴가 종류는 지울 수 없습니다.
- **휴가원 영구 삭제:** 휴가원을 먼저 취소한 뒤 상세 창의 `영구 삭제`를 누릅니다 (삭제된 직원의 휴가원은 취소 없이 바로). 지우기 직전에 자동으로 백업을 만듭니다.
- 잘못 지웠다면 관리 > 백업·업데이트에서 `영구 삭제 전` 백업으로 복구하세요 (그 뒤에 입력한 내용은 사라집니다).

## 6. 백업과 복구

### 자동 백업

- 매일 `backupTime`(기본 12:30)에 DB를 `<설치 폴더>\backups`에 백업하고, `nasBackupDir`이 있으면 **NAS에도 복사**합니다.
- 그 시각에 PC가 꺼져 있었으면 켜진 뒤 바로 백업합니다.
- NAS가 잠깐 꺼져 있거나 응답하지 않아 NAS 복사에 실패하면, 그날 안에 **1시간마다 NAS 복사만 다시** 합니다.
  서버를 다시 켰을 때 오늘 자동 백업이 NAS에 없으면 그때도 NAS로 복사합니다.
- `backupKeepDays`(기본 30일)보다 오래된 백업은 자동으로 지웁니다 (`leave-flow-날짜-시각-….db` 이름의 파일만).
- 파일 이름 끝의 말: `daily`(자동), `manual`(지금 백업), `pre-restore`(복구 직전), `pre-update`(업데이트 직전), `pre-delete`(영구 삭제 직전)

### NAS 백업 설정과 계정

- 관리 → **설정** → **NAS 백업 폴더**에 ipTIME NAS2의 공유폴더 주소를 넣고 **저장**합니다. 예: `\\NAS주소\backup\leave-flow`
  저장할 때 그 폴더에 시험 파일을 써 보고, 쓸 수 없으면 이유를 보여 주고 저장하지 않습니다.
  저장한 값은 `config.json`의 `nasBackupDir`에 기록되고, 다시 시작하지 않아도 다음 백업부터 적용됩니다. 비워 두고 저장하면 NAS 백업을 끕니다.
  (`update-config.ps1 -NasBackupDir`로 바꿔도 됩니다.)
  (이 안내서의 `NAS주소`는 NAS의 실제 IP 주소로 바꿔 쓰세요. NAS 관리 화면이나 공유기의 연결 목록에서 확인할 수 있습니다.)
- leave-flow는 출결 PC에 **로그인한 Windows 계정**으로 실행되므로, NAS에도 그 계정으로 접근합니다.
  1. NAS 관리 화면에서 공유폴더에 접근할 사용자를 만들고 쓰기 권한을 줍니다.
  2. 출결 PC의 그 계정에서 탐색기 주소창에 NAS 주소를 넣고, 로그인 창이 나오면 NAS 사용자로 로그인하며 **자격 증명 기억**을 체크합니다.
     (확인: 그 공유폴더에 새 폴더를 만들 수 있는지)
  3. 그 뒤 관리 → 설정에서 NAS 백업 폴더를 저장합니다.
- NAS 복사에 실패해도 로컬 백업은 정상적으로 만들어지고, 관리 화면 **백업·업데이트**에 오류가 빨간 글씨로 표시됩니다.

### 지금 백업 / 복구 (관리 화면)

관리 → **백업·업데이트**

- **지금 백업**: 바로 백업합니다 (로컬 + NAS).
- **백업 파일** 목록에서 원하는 시점의 **복구**를 누르면:
  1. 지금 데이터를 먼저 백업하고(`pre-restore`),
  2. 선택한 백업으로 바꾼 뒤 서버를 다시 시작합니다 (모든 직원의 화면이 잠깐 끊깁니다).
  3. 그 백업 이후에 입력한 내용은 사라집니다. 잘못 복구했으면 `pre-restore` 백업으로 다시 복구하면 됩니다.
  - 복구할 때마다 "복구 전" 백업이 두 개(복구를 누른 순간, 실제로 바꿔 끼운 순간) 생깁니다. 내용은 같으니 어느 쪽을 써도 됩니다.
  - 최근 백업 일시·업데이트 기록 같은 시스템 정보는 복구해도 되돌아가지 않습니다.

### 서버가 시작되지 않을 때 직접 복구

1. 트레이 아이콘의 **종료**로 서버를 끕니다 (트레이가 없으면 관리자 PowerShell에서 `Stop-ScheduledTask leave-flow`).
2. 원하는 백업 파일을 `<설치 폴더>\data\restore-pending.db` 이름으로 복사합니다.
3. 다시 시작합니다. 서버가 시작하면서 지금 DB를 `backups\`에 보관하고 복구 파일로 바꿉니다.

### 엑셀 백업

관리 → 백업·업데이트 → **엑셀로 내려받기**: 직원, 휴가 종류, 부여 내역, 기존 잔여량, 휴가원, 휴가원 항목, 시간외근무 신청서,
공휴일·휴무일, 사용 현황 요약(올해), 변경 이력을 시트별로 담은 `.xlsx` 파일을 받습니다.
보관·확인용이며, **엑셀 파일로 복구할 수는 없습니다** (복구는 DB 백업 파일로).

## 7. 자동 업데이트

### 동작

- 서버가 시작되고 약 2분 뒤, 그리고 `updateCheckHours`(기본 6시간)마다 GitHub Releases에서 새 버전을 확인합니다.
  `autoUpdate`가 `false`여도 확인은 하므로 관리 화면에 최신 버전과 **새 버전** 표시가 나옵니다.
- 새 버전이 있고 `autoUpdate`가 켜져 있으면: 내려받기 → **파일 무결성(SHA-256) 확인** → **DB 자동 백업**(`pre-update`) → 새 버전 설치 → 서버 재시작.
- DB 구조 변경(마이그레이션)은 새 버전이 시작할 때 자동으로 적용됩니다.
- 새 버전이 **60초 안에 정상적으로 응답하지 않으면 이전 버전으로 자동으로 되돌리고**, 업데이트 직전 DB 백업도 함께 되돌립니다.
  실패한 버전은 자동으로 다시 설치하지 않습니다 (관리 화면에 안내가 나오고 변경 이력에 남습니다. 더 높은 버전이 나오면 그 버전을 설치합니다).
- 관리 화면 **백업·업데이트**에서 현재 버전, 최신 버전, 최근 확인·업데이트 일시를 볼 수 있고,
  **업데이트 확인**·**지금 업데이트** 버튼으로 직접 할 수도 있습니다.
- 자동 설치를 끄려면 `autoUpdate`를 `false`로 — `update-config.ps1 -AutoUpdate off` (확인과 관리 화면에서 직접 업데이트는 가능).
  기능 자체를 끄려면 `updateRepo`를 `null`로 — `update-config.ps1 -DisableUpdates`.
- 서버를 감시하는 `launcher.mjs`는 새 버전이 정상 기동한 뒤 파일만 바꿔 두고, **다음에 트레이로 다시 켤 때(PC 재시작·로그인 포함)부터** 새 것이 쓰입니다.
- 인터넷이 끊겨 있으면 확인만 실패하고 프로그램은 그대로 동작합니다.

### 새 버전 배포 (개발자)

1. 코드를 고치고 `npm test`, `npm run typecheck`로 확인합니다.
2. 루트 `package.json`의 `version`을 올립니다. 예: `npm version patch --no-git-tag-version` (0.1.0 → 0.1.1)
3. 커밋하고 같은 버전의 태그를 push 합니다.
   ```sh
   git commit -am "0.1.1"
   git tag v0.1.1
   git push && git push --tags
   ```
4. GitHub Actions(`release`)가 테스트·타입 검사·빌드 후 Release에 `leave-flow-0.1.1.zip`과 `.sha256`, 설치 프로그램 `leave-flow-setup-0.1.1.exe`를 올립니다.
   태그와 `package.json` 버전이 다르면 실패합니다.
5. 사무실 서버는 다음 확인 때(최대 `updateCheckHours`) 자동으로 설치합니다. 바로 적용하려면 관리 화면에서 **지금 업데이트**.

> 공개 저장소이므로 DB, 백업, 직원 정보, `config.json`은 절대 커밋하지 않습니다.

## 8. 문제 해결

### 접속이 안 될 때

1. **출결 PC에서** `http://localhost:8080`이 열리는지 확인합니다.
   - 열리지 않으면 서버가 실행되지 않은 것입니다 → 아래 "로그 위치"에서 오류를 확인하고, PC를 다시 켜 보세요.
   - 트레이에 파란 달력 아이콘이 있는지 확인합니다. 없으면 시작 메뉴의 **leave-flow 휴가원 관리**로 켭니다.
   - 켜자마자 "서버가 종료되었습니다" 창이 나오면 그 창에 적힌 로그 폴더에서 이유를 확인합니다.
2. 출결 PC에서는 되는데 다른 PC에서 안 되면:
   - 네트워크 프로필이 **개인**인지 (2장 참고)
   - 방화벽 규칙 `leave-flow`가 있는지 (설치를 다시 실행하면 다시 만듭니다)
   - 출결 PC의 **IP가 바뀌지 않았는지** (명령 프롬프트에서 `ipconfig`) → 공유기에서 IP 예약
3. "서버에 연결할 수 없습니다"가 잠깐 보였다가 사라지면 업데이트·복구로 서버가 다시 시작된 것입니다.

### 포트 충돌

`8080번 포트를 이미 다른 프로그램이 사용 중`이라고 나오면 다른 포트를 씁니다.
`update-config.ps1 -Port 8090` (설치 전이면 `install.ps1 -Port 8090`). **5000번은 auto-ansimtalk 전용이라 쓸 수 없습니다.**
포트를 바꾸면 직원들의 접속 주소(즐겨찾기)도 바꿔야 합니다.

### 로그 위치

- `<설치 폴더>\logs\server-YYYYMMDD.log` — 서버와 launcher 기록 (날짜별, 30일 보관)
- 관리 화면 → **변경 이력**: 백업·복구·업데이트 기록도 남습니다.

### 업데이트에 실패했을 때

- 새 버전이 정상적으로 시작되지 않으면 **자동으로 이전 버전으로 되돌립니다**. 관리 화면 백업·업데이트에 노란 안내가 나오고,
  `state.json`의 `lastUpdateError`에 이유가 남습니다. 같은 버전은 자동으로 다시 설치하지 않습니다.
- 내려받기·무결성 확인에 실패하면 아무것도 바뀌지 않습니다. 다음 확인 때 다시 시도합니다.
- 업데이트 전 백업(`pre-update`)이 항상 있으니, 데이터가 이상하면 그 백업으로 복구할 수 있습니다.

### 새 버전에 문제가 있어 이전 버전으로 돌아가고 싶을 때

1. GitHub Releases에서 이전 버전의 설치 프로그램(`leave-flow-setup-<버전>.exe`)이나 zip을 받아 다시 설치합니다 (1장 "다시 설치·버전 바꾸기").
   설치하기 전에 지금 DB를 `pre-update`로 백업합니다.
2. 낮은 버전으로 바꾸면 자동 업데이트가 문제 있는 버전을 **다시 설치하지 않도록 건너뜁니다** (설치 창에 노란 안내).
   그보다 높은, 문제를 고친 버전이 나오면 자동으로 설치됩니다.
3. 새 버전이 나와도 이 버전에 계속 머물려면 `update-config.ps1 -AutoUpdate off`로 자동 설치를 끄세요.
   나중에 다시 켜려면 `-AutoUpdate on`.
4. 새 버전에서 DB 구조가 바뀌었다면 이전 버전에서 일부 화면이 이상하게 동작할 수 있습니다. 그때는 관리 화면에서
   그 새 버전으로 업데이트하기 직전 백업(`pre-update`)으로 복구하세요 (6장, 그 뒤에 입력한 내용은 사라집니다).

### NAS 백업 오류

관리 화면에 `NAS 복사 실패`가 보이면: NAS가 켜져 있는지, 주소가 맞는지, 출결 PC에 로그인한 Windows 계정이 그 폴더에 쓸 수 있는지(6장) 확인하세요.
로컬 백업은 계속 만들어집니다.
