# 문제 해결

## 접속이 안 될 때

1. **출결 PC에서** `http://localhost`가 열리는지 확인합니다.
    - 열리지 않으면 서버가 실행되지 않은 것입니다 → 아래 [로그 위치](#로그-위치)에서 오류를 확인하고, PC를 다시 켜 보세요.
    - 트레이에 파란 달력 아이콘이 있는지 확인합니다. 없으면 시작 메뉴의 **leave-flow 휴가원 관리**로 켭니다.
    - 켜자마자 "서버가 종료되었습니다" 창이 나오면 그 창에 적힌 로그 폴더에서 이유를 확인합니다.
2. 출결 PC에서는 되는데 다른 PC에서 안 되면:
    - 네트워크 프로필이 **개인**인지 ([접속 주소와 네트워크](../general/network.md#방화벽))
    - 방화벽 규칙 `leave-flow`가 있는지 (설치를 다시 실행하면 다시 만듭니다)
    - 출결 PC의 **IP가 바뀌지 않았는지** (명령 프롬프트에서 `ipconfig`) → 공유기에서 IP 예약
3. "서버에 연결할 수 없습니다"가 잠깐 보였다가 사라지면 업데이트·복구로 서버가 다시 시작된 것입니다.

## 포트 충돌

`80번 포트를 이미 다른 프로그램이 사용 중`이라고 나오면 다른 포트를 씁니다.
`update-config.ps1 -Port 8090` (설치 전이면 `install.ps1 -Port 8090`). **5000번은 auto-ansimtalk 전용이라 쓸 수 없습니다.**
포트를 바꾸면 직원들의 접속 주소(즐겨찾기)도 바꿔야 합니다.

## 로그 위치

- `<설치 폴더>\logs\server-YYYYMMDD.log` — 서버와 launcher 기록 (날짜별, 30일 보관)
- 관리 화면 → **변경 이력**: 백업·복구·업데이트 기록도 남습니다.

## 업데이트에 실패했을 때

- 새 버전이 정상적으로 시작되지 않으면 **자동으로 이전 버전으로 되돌립니다**. 관리 화면 백업·업데이트에 노란 안내가 나오고,
  `state.json`의 `lastUpdateError`에 이유가 남습니다. 같은 버전은 자동으로 다시 설치하지 않습니다.
- 내려받기·무결성 확인에 실패하면 아무것도 바뀌지 않습니다. 다음 확인 때 다시 시도합니다.
- 업데이트 전 백업(`pre-update`)이 항상 있으니, 데이터가 이상하면 그 백업으로 복구할 수 있습니다.

## 새 버전에 문제가 있어 이전 버전으로 돌아가고 싶을 때

1. GitHub Releases에서 이전 버전의 설치 프로그램(`leave-flow-setup-<버전>.exe`)이나 zip을 받아 다시 설치합니다 ([설치](../getting-started/installation.md#다시-설치버전-바꾸기)).
   설치하기 전에 지금 DB를 `pre-update`로 백업합니다.
2. 낮은 버전으로 바꾸면 자동 업데이트가 문제 있는 버전을 **다시 설치하지 않도록 건너뜁니다** (설치 창에 노란 안내).
   그보다 높은, 문제를 고친 버전이 나오면 자동으로 설치됩니다.
3. 새 버전이 나와도 이 버전에 계속 머물려면 `update-config.ps1 -AutoUpdate off`로 자동 설치를 끄세요.
   나중에 다시 켜려면 `-AutoUpdate on`.
4. 새 버전에서 DB 구조가 바뀌었다면 이전 버전에서 일부 화면이 이상하게 동작할 수 있습니다. 그때는 관리 화면에서
   그 새 버전으로 업데이트하기 직전 백업(`pre-update`)으로 복구하세요 ([복구](../backup/restore.md), 그 뒤에 입력한 내용은 사라집니다).

## NAS 백업 오류

관리 화면에 `NAS 복사 실패`가 보이면: NAS가 켜져 있는지, 주소가 맞는지, 출결 PC에 로그인한 Windows 계정이 그 폴더에 쓸 수 있는지([NAS 백업 설정과 계정](../backup/nas.md#nas-백업-설정과-계정)) 확인하세요.
로컬 백업은 계속 만들어집니다.
